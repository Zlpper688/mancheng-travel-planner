# 漫城 MANCHENG

从一间酒店出发的城市漫游计划。选择目的地、落脚点、游玩天数与偏好，自动生成每天从酒店出发、最后回到酒店的闭环行程，并在真实地图上展示「点 = 停留、线 = 路程」。

## 快速开始

```bash
npm install
cp .env.example .env.local   # 可选：填入高德 Key
npm run dev                  # http://localhost:3000
```

生产构建：

```bash
npm run build
npm start
```

## 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `AMAP_KEY` | 否 | 高德开放平台「Web 服务」Key。配置后启用任意城市的真实 POI、商户评分/营业信息、公交/地铁换乘与驾车路线。 |

未配置 `AMAP_KEY` 时会自动进入免 Key 模式：

- 厦门使用内置演示点位（坐标为真实地点，门票/均价为参考值）。
- 其他城市使用 OpenStreetMap / Wikidata 点位与 Photon 地理编码，步行和驾车路线使用 FOSSGIS OSRM 真实路网。
- 公交耗时、部分票价与拥挤度为估算，界面会标注「估算」。
- 高德中文底图通过公开瓦片服务加载，不依赖 Key；服务端统一使用 WGS84，地图展示层自动转换为 GCJ-02。

> 本机网络对 `overpass-api.de` 返回 406 时，点位会降级到 Wikidata 知名地标，并在「说明」中提示。配置高德 Key 可获得完整城市数据。

## 功能

- 目的地城市：快捷城市、搜索城市、地图任意点。
- 落脚点：搜索酒店/民宿/地标，或直接在地图上点选，自动反向地理编码。
- 行程闭环：每天从酒店出发并回到酒店；景点、正餐、咖啡茶歇混排，中午留出用餐窗口。
- 每日主轴：每天先锁定一个主景和一个收尾（日落机位或夜市亮灯），中间再补同片区的支撑点；行程卡显示当天主题、主景和一句「走法」，午后空出两小时以上时自动补一个顺路点位或咖啡茶歇。
- 夜市晚饭：收尾在夜市/小吃街的日子，晚饭优先留在收尾那片，午饭避开同一片，避免晚上折返几公里去吃饭。
- 排线取舍：日落/夜市日按更晚的回家时间计算；超时先撤可选茶歇、再撤支撑点，不砍主景与收尾。撤点会说明原因，同片区已有点位时提示「吃完顺路逛即可」。
- 大景与远足日：集美、植物园这类 3–5 小时的大景可以独立成日；早上开窗的大景先走完再回城，右对齐到傍晚的日子会给午饭预留一小时，避免午饭把下午整体后移、摸黑才到主景。日落点如果被前序点位挤到天黑后，先撤掉非锚点的晚段支撑把它拉回来；名气一般的日落点不为它牺牲白天主景。
- 旅行风格：城市漫步、精华打卡、环海慢游、文化深度、寻味本地、亲子轻松（最多 3 个）。
- 节奏：松弛 / 适中 / 充实，控制每日停留点数量与停留时长。
- 远足天数：自动 / 就近 / 1 天 / 2 天；把较远但出名的景点单独成日，远足日只走一个方向，其余天留在酒店附近。
- 交通：自动、多走路、公交优先、打车为主；厦门会结合地铁 1/2/3 号线比较「地铁 vs 打车」的耗时与费用，两端步行超过 1.4 km、或换乘绕路明显更慢时自动回落公交/打车；每段路显示方式、耗时、距离、费用与备选方式，地铁段带线路、换乘次数和出入站步行时间。
- 地铁进出站：厦门有地铁覆盖的点位会显示「地铁 · 镇海路 700m」标签；集美学村、园博苑、五缘湾、邮轮中心等地铁可达片区会优先成团。
- 节假日与周末：按日期识别人流系数，放宽热门点位的路上时间。
- 天气与日照：逐日取当天首个点位所在区域的天气（温度、逐小时降水、风、日出日落），展开某天可看到 24 小时气温曲线与降水柱状图；下雨时给一条同区域室内备选，户外点位跨过日落会提示；出行日期超出 16 天预报窗口时自动改用去年同期气候参考并标注。
- 天气排线：预报日早上有雨且稍后转好时推迟出发；户外点位落在雨段会适当收紧停留、在点位备注里标明雨段；按点位所在时段的气温提示防晒补水或保暖，高温时再缩短 10 分钟户外停留；远期行程只按去年同期气候做提示，不改动时间轴。
- 场景贴士：按城市、点位类型、亲子/慢节奏、节假日人流、轮渡/海岛、海鲜市场、寺庙、博物馆周一闭馆、拍照日落、交通换乘等条件，为每天挑最多 3 条、整趟最多 5 条可执行的小贴士，并标注来源；规则、价格与班次以官方最新公告为准。
- 景点属性与点位移贴士：时间轴上的每个停留点带「预约 / 最佳时段 / 建议停留」标签，并先显示 2 条现场贴士，可展开到 4 条；内置约 90 个景点档案（覆盖厦门全部演示点位，以及杭州、北京、成都、青岛、三亚的主要景点），包含放票节奏、入口与动线、拍照机位、吃法、防坑、雨天和带娃建议；未收录点位按类别自动兜底。
- 换一版：同一组偏好下改用新 seed，重新做锚点轮换与 2-opt 闭环。
- 攻略导入：粘贴整段游记，按 Day/中文数字识别分组，匹配地点并按原文顺序复刻；可勾选/取消每天的点位。
- 预算：住宿晚数/房间数、节假日房价上浮、餐饮实际人均或档位补齐、门票区间、交通按人/车、零花机动，输出总价与人均区间。
- 地图：高德中文底图、编号停留点、酒店标记、实线真实路径/虚线估算路径、点击点位聚焦弹窗。
- 响应式：移动端按「地图 → 行程 → 设置」排列；桌面端为 392px 设置侧栏 + 地图 + 行程。

## 算法概览

1. **点位发现**：优先高德 POI；免 Key 时 Overpass 查询景点与餐饮，不足则用 Wikidata 地标补齐，并过滤连锁餐厅。
2. **体验优先评分**：名气、必去标签、评分是主项，风格只做加分；低口碑远点同时吃「名气不足」和「距离过远」两道惩罚，避免为了凑数把 40 分钟车程的公园塞进行程。
3. **每日骨架与主景**：每天先锁一个高名气主锚点（鼓浪屿、南普陀/厦大、中山路/八市/沙坡尾、植物园等），并识别早市、日出、日落、夜市等时间角色；同类片区自动合并，同时避免把两个日落点或两个商业街排在同一天。早市也尽量不跟日落/夜市同天——早市接夜市会在午后留下大段空档。只有傍晚才进入状态、名气又不够的普通点位（海堤、街心公园之类）不当锚点，避免为了一个黄昏点跑很远或撑起一整天。行程卡展示当天主题、主景与「走法」。
4. **锚点聚类分日**：其余点位按「离哪个锚点最近、是否同岛、是否共用地铁线」分配到当天，每天控制在 3–6 km 的片区半径内；亲子、城市漫步、松弛节奏自动收紧半径，打车为主略放宽。带日落/夜市收尾的日子多留一个支撑位和 90 分钟时长，避免中午到傍晚空一大段。5 天以上允许「半天型大景」（集美、植物园）独立成日，不再强行并进邻近片区。固定日期、远足日与近处日期分开计算。
5. **远足日**：把车程较远的著名点位单独成日——先选名气主锚点，再收拢同方向、16 km 内顺路点位；默认按名气和距离自动安排 1–2 天，也可手动选「就近 / 1 天 / 2 天」。远足日连续且居中排在行程里（例如 5 天行程排在第 3、4 天），前一天/后一天留在酒店附近，整天只走一个方向；没人气点位时自动减天并提示。
6. **闭环排线与通勤方式**：每天做最近邻初排 + 2-opt 闭环优化；通勤时比较步行、公交、地铁与打车，地铁只在「两端步行都合理、总耗时接近或优于打车」时采用，绕行换乘或短距离不划算时自动改公交/打车；跨海段仍走轮渡并预留候船时间。
7. **一日一条时间主轴**：白天开场（远足出发、日出、早市、上午型寺庙）→ 午后支撑点 → 日落机位/夜市亮灯收尾；先定收尾，再把中间点位排进时间轴，避免晚上为了补点折返。收尾日采用右对齐时会给午饭预留一小时，防止午饭插入后下午整体后移；早上有窗口的半天型大景（植物园）优先走早上，日落前再接城市里的收尾点。
8. **建议时段不是开门闸门**：景点档案里的「最佳时段」（如「9:30 前 / 15:00 后」）只做软引导；真正安排等待的只有日落（提前 30 分钟到机位）、夜市亮灯（17:30 后）和下午才开门的点位，且空等上限两小时。其余点位到得早就先逛起来，不再为一句「15 点后更热闹」制造两三小时空档。
9. **空档补位与下午茶**：午后空出两小时以上时，从当天未使用的同片区点位里补一个，并保证回程不因此显著变长；有咖啡点位时把茶歇放在 15:00 前后，正好落在日落/夜市之前。可选茶歇如果导致超时会被自动撤回，不挤掉主景。
10. **餐食插入**：按午餐/晚餐窗口挑顺路餐饮，并强制同岛匹配，避免为了吃一顿饭把行程拉去坐轮渡；收尾是夜市/小吃街的日子，晚饭优先留在收尾那片，午饭避开同一片，防止晚上折返几公里；花生汤、早点这类早餐属性餐点不会被排成晚饭。数据不足时预留用餐时间并给出提示。
11. **时间轴与取舍**：叠加开放时间、用餐窗口、人流系数与节奏参数；超出回家时间时先撤可选咖啡、再撤支撑点，主景、日落和夜市锚点保留。日落/夜市日允许比普通日多玩 45 分钟。日落点如果排到日落 20 分钟后，先把非锚点的晚段支撑点撤掉重排，把日落拉回天黑前；如果这个日落点名气一般（<4.1），则不为了它挤掉白天主景，直接放弃日落并说明原因。撤点会说明原因，同片区已有点位时提示「吃完顺路逛即可」。
12. **攻略模式**：解析出的地点按原文 Day 与顺序锁定，餐食/咖啡只做补充插入，不再打乱原有顺序。
13. **天气情报**：按每天首个点位取 Open-Meteo 预报，同时取逐小时降水量、降水概率与气温，生成 24 小时气温曲线、雨情图、雨具、防晒、保暖与日落提示；有雨时从同区域未入选的博物馆里挑一个室内备选。预报窗口外自动换用去年同期气候，避免把远期行程说成确定天气。
14. **天气排线**：把逐小时降水与气温叠进时间轴——早上下雨且两小时内转好时，出发时间最多推迟 90 分钟；户外点位与明显雨段重叠时，按雨势收紧 10–20 分钟停留，并在点位备注与「出发前留意」里标明雨段；按点位所处时段的气温提示防晒补水或保暖，达到 35°C 时再缩短 10 分钟户外停留并点出当天最晒的点位。去年同期气候只做提示，不推动行程改点。
15. **场景贴士**：把公开攻略与景区/交通公告提炼成带触发条件的贴士库，按城市（厦门轮渡/厦大/南普陀/八市、杭州灵隐/西湖、北京故宫/国博、成都熊猫基地）、点位类别与标签、亲子、节假日人流、雨天/高温/低温、海岛轮渡、海鲜市场、寺庙礼仪、拍照日落、公共交通与防坑等条件匹配；按命中精度打分，同组去重，每天最多 3 条、整趟最多 5 条，并标注来源。远期气候数据不触发具体雨段贴士。
16. **景点属性层**：把景区公告与实地攻略沉淀成点位档案（放票节奏、最佳时段、建议停留、入口/动线、拍照机位、吃法、防坑、雨天与带娃建议），按城市 + 名称匹配到当天每个停留点，转成属性标签和 2–4 条贴士；档案未覆盖的点位按博物馆/海滩/寺庙/市场/自然/观景/餐饮/街区等类别兜底。名称匹配优先更长的词条，避免「曾厝垵」命中「曾厝垵小吃街」这类街区档案。
17. **预算**：按真实标价优先、同档中位数补齐的方式计算区间，并说明每一项的假设。

服务端缓存：点位发现 10 分钟，天气 30 分钟，路线 6 小时，减少重复请求。

## 已知限制

- 门票、人均、房价为区间估算，预订前需以商家页面为准。
- 公交线路与班次在免 Key 模式下为估算；配置 `AMAP_KEY` 后更准确。
- 地铁数据目前覆盖厦门 1/2/3 号线（站点坐标来自 Wikidata / OSM）；厦门地铁 3 号线南延段（厦大/沙坡尾/曾厝垵）截至 2026 年尚未开通，因此环岛南路一带仍按公交/打车安排。其他城市未内置地铁数据，会沿用高德公交换乘或估算。
- 地铁耗时按站间距离、停站、候车与换乘 5 分钟估算，未接入实时班次与首末班车；出发前用官方 App 复核末班时间。
- Overpass 不可达时，非演示城市会退化为 Wikidata 地标，点位数量与餐饮丰富度会下降。
- 跨海/跨岛行程按轮渡预留时间，但未接入实时船班。
- 天气为 Open-Meteo 网格预报（约 1–11 km 分辨率），山区与海岛微气候可能偏差；逐小时气温也是网格值，点位体感还会受日照、风和树荫影响；行程日期超出 16 天时只提供去年同期气候参考，不是预报，逐小时数据更适合当趋势看。
- 逐小时降水与气温用于排线时取的是网格预报值；雨带移动、局地强对流、城市热岛都可能造成偏差，出发当天以雷达和现场为准。
- 场景贴士与景点档案来自公开攻略、景区/交通公告的提炼，预约规则、放票时间、票价、船班、闭馆日、入口开放状态与营业时间都会调整；已尽量保留「以官方为准」，出发前仍需核对官方渠道。
- 景点的「最佳时段」是攻略经验的提炼，不是官方营业时间；排程只把它当软建议，临时闭园、限流与末班车仍以官方为准。没有标注日落的「傍晚型」点位按通用傍晚时间收尾，实际天色以当天日落为准。
- 免 Key 模式下非演示城市可能没有足量的咖啡/餐饮点位，午后补位与下午茶会退化为预留时间或直接跳过；配置 `AMAP_KEY` 后补位选择更丰富。
- 攻略解析只识别文中明确出现的地点名称；模糊描述（如「附近吃海鲜」）会列为未识别片段。
